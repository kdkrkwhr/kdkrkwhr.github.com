# 블로그 글 스타일 가이드 (DK 기술 블로그)

기존 `_posts/` 글들과 동일한 톤·구조를 따른다.

## Front matter (YAML)

```yaml
---
layout: post
author: Kim, DongKi
title:  "글 제목"
date:   YYYY-MM-DD
categories: AI
comments: true
---
```

- `categories`: AI 글은 `AI`, 인프라/DevOps 성격이면 `devOps`, 일반 기술이면 `Technology`
- `date`: 실행 당일 날짜
- 파일명: `_posts/YYYY-MM-DD-slug.md` (slug는 영문 소문자·하이픈)

## 본문 구조

1. `### TL;DR` — 3~5줄 요약 (불릿 `*` 또는 짧은 문단)
2. `----` 구분선
3. `### 들어가며` — 주제 도입, 개인 경험·느낌 (1~2단락)
4. `----` 구분선
5. 본문 섹션 — `###`, `####` 헤딩, `----`로 구역 분리
6. 코드 블록은 언어 태그 명시 (```bash, ```yaml 등)
7. 이모지 가끔 사용 OK — 과하지 않게

## 노트버디 개발기 말투 (2026-10-19 사용자 피드백)

- 1~3편에 적용한 말투를 후속 편에서도 유지한다. 위 Copilot·FCM 글처럼 독자에게 개발 경험을 이야기하는 부드러운 존댓말을 사용한다.
- `~했습니다`만 반복하지 않고 `~해봤습니다`, `~더라고요`, `~고요`, `~해보려 합니다`를 문맥에 맞게 섞는다. 단순히 문장 끝만 바꾸지 말고, 상황과 선택 이유가 자연스럽게 이어지도록 쓴다.
- 도입, 이미지 설명, 표, 마무리까지 같은 말투를 사용한다. 독자에게 보여주는 실제 인용과 코드는 그대로 둔다.
- 이모지는 도입 등에 가볍게 사용한다. 친근함을 위해 없던 경험이나 감정, 결과를 만들어내지는 않는다.
- 기술적 사실, 버전과 수치, 검증 범위, 이미지 출처와 링크는 말투를 다듬을 때도 보존한다.
